## 一、裁定全集

1. **choice 图无边（T3）**：M2 schema 无 choice→choice 指向字段（consequence 是纯文本），
   「关键选项」图 = 按章分列的节点集合、`edges` 恒空；列 x 用章在全书 order 序列的**全局位置**
   （前章无选项不借位）。若未来 schema 出现分支间因果字段，再补边——测试已把 `edges: []` 钉死。
2. **arc 选择器默认主角（T4）**：`buildArcGraph` 的角色默认值 = 名字 localeCompare 全序中**首个
   `role==='protagonist'`**，无主角回落全序首个；选择状态**随 kind 重置**（离开「角色成长」档即
   清本地选择，回来重算默认）；选中角色被删时 find 脱靶自动回落，不留悬空 id。
3. **跳转空引用回退（T4/T5）**：节点点击先查「实体→章节」引用并集（`.ai/index.json` ∪ 显式字段，
   纯函数 `buildEntityChapterRefs` 去重/剔悬挂/书序排列）：有引用弹「出现章节」菜单，无引用回退
   M3 行为切侧栏面板——character/arc→「角色」、world→「设定」、plotline/choice→「叙事」。
   跳章 = 新定位语义，落点不复活旧视图态（见裁定 5）。
4. **narrow-gate 统一（T6）**：foreshadow/summary/index 的 update 未知键由「静默丢弃」改**整条拒**
   （`adopt.ts` `assertNoUnknownUpdateKeys`，reason 与 character/world 逐字同形 `未知字段 <key>`）；
   静默丢弃会让采纳账目说谎。create×summary/index 维持 buildCandidate 宽容口径（brief 圈定）；
   保留回显集（id/createdAt/updatedAt/aiTouched/status/aiSource）仍静默剥离；面板陈年注释同步翻案。
5. **viewState 方案选型：chapter-paired ref（T6 + 评审 R1）**：「写作↔图谱」切换用 Workspace 一个
   `{chapterId, state}` ref——离开写作前存、切回后**比对章 id 才恢复**（一次性消费+清空），错章静默
   丢弃。否决方案：把视图态塞进 useEditorSession 持久层（动内容保存主链，收益不成比例）、
   按章 map 缓存（无界增长 + 语义超前需求）。R1 实证：图谱态经侧栏树换章后切回写作，
   A 章光标绝不复活进 B 章内容；跳章菜单路径显式清空保留（跳章=新定位）。
6. **T1 legacy no-cid hit-skip 取舍 = ACCEPT**：无 cid 第三方提案的位置回退键（`idx:N`）照常盖
   `aiSource` 令牌并参与命中跳过——reject 重排后复用的位置键可能命中重排前盖章的陈旧令牌，
   导致一次创建被按「已应用」跳过。三重交集的角加角（legacy 无 cid × reject 重排 × 同域 create），
   应用盖章提案恒有真 UUID cid 免疫；备选（legacy 不盖章/不扫描）直接违反钉死的重试幂等测试、
   重开双胞胎窗。已成文 BOOK_FORMAT §7.5/§8 守则 14，测试钉死新语义。
7. **T5 越界接线 = 占位的定点兑现，ACCEPTABLE**：Ctrl+3「情节线索」与图谱无引用 plotline/choice
   节点回退两处，源码注释本就写明「Task 5 接入后补映射」——T5 顺路兑现（各 ≤5 行、revert-safe），
   评审裁定属完成承诺而非 scope creep；GraphKind 五键消费就此全覆盖。
8. **台账坏值的两副面孔（T7 收口，本文档落定）**：
   - **图谱侧静默降级**（`withLedgerFallback`，T4-fix R1）：图谱是只读展示，五 builder 均不吃
     台账，坏 `foreshadow.yaml` 只让伏笔跳章引用缺席，warn 留痕即可——白屏/冻结的代价大于收益。
   - **整理侧 fail-loud**（`withLedgerLoudError`，随本收尾的 `fix(organize)` 提交落地）：整理消耗
     用户 token，若同样静默降级成空台账，AI 上下文里的伏笔部分会**无声蒸发**、照常产出「看起来
     正常」的提案——欺骗性大于报错。维持抛穿中止，并把错误文案从裸英文
     `整理失败：FORESHADOW_INVALID: <path>: …` 收口进中文词表单源
     （`整理失败：伏笔台账数据已损坏，应用未做任何修改：…`，原 error console.error 留痕）。
     两侧不对称是**刻意设计**，注释互引防止后来者"统一"掉。
9. **取消整理竞态语义（T6）**：装配窗口（getAISettings + 六路拉数，毫秒级）无 requestId，点「取消」
   静默 no-op——不造「预备取消」状态机；`ai:cancel` 返回 false（请求恰好自行收尾）= 正常完成路径
   赢，不弹取消成功、提案照常生成。真机冒烟各走一遍：取消成功一次、完整跑通一次（T7 实测：
   真 key 下 450ms 偏移点「取消」竞得在途 → toast「已取消整理」；同一章再整理自然跑通 →
   「整理提案已生成（1 条变更）」）。
10. **console 红线口径收口（T7）**：真机总冒烟确立「零 console 错误」红线计**应用可归因错误**
    （栈含 `src/renderer` 帧或应用语义的 reject），两类上游 dev-only 产物单列记录、不判负：
    - monaco 内部 `Canceled: Canceled` 未捕获 reject（栈全在 monaco chunk：`Delayer.cancel ←
      restore ← restoreViewState`）——由 T6 视图态恢复触发，恢复功能本身经游标行号断言实证无损；
      上游异步 delayer 取消的既有形态，应用层无 promise 可挂 catch。结转 minor：评估把
      pending-apply 延后一帧是否能消除噪声（若易行）。
    - antd `rc-util isEqual` 的 `warningOnce('There may be circular references')` dev 警告——
      栈全在依赖 chunk（无应用帧），prod 构建 dev warning 被摘除；出现于设置表单/提案弹窗重度
      diff 期。结转 minor：定位触发 antd isEqual 深比较的 props（候选：Segmented options 携带
      JSX label 的身份抖动，可 useMemo 稳定）。
11. **点击时配置门维持**（M4b 终审裁定沿用）：未配置 key 时「整理本章」入口可点、点击时校验并
    中文 toast 指引，不做置灰快照——状态更新鲜、一次点击得指引。
