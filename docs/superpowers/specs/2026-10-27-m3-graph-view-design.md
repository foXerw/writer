# M3：图谱视图 设计文档（AI 代拟，待发起人复核）

日期：2026-10-27 ｜ 状态：发起人授权 AI 代定设计后开发（"你来设定后进行开发"）；所有 ⚑ 标记的选择均可一键推翻
上游规格：`2026-10-25-perfect-novel-repositioning-design.md` §7.2（实体-关系-事件模型）、§8（M3 行：先交付人物关系图 + 世界观图两种）
数据基础：M2 已落地的 v2 文件模型（characters/*.yaml 的 relationships、world/*/*.yaml 的 parentId/links）

## 1. 意图

把 M2 那份"实体-关系"数据**画成可看的图**，让作者一眼看清人物关系网与世界观层级——这是本项目区别于普通写作工具的第一个可见差异点。M1 已在 Workspace 用 `renderMainView()` 预留了图谱视图的接缝，本里程碑兑现它。

## 2. 目标

- G1 图谱视图：主区新增"图谱"视图，与"写作"视图通过顶部分段控件切换（复用 M1 的 renderMainView 接缝）。
- G2 人物关系图：节点=角色，边=关系（kind 作边标签），自动径向布局。
- G3 世界观图：节点=设定条目（按分类着色分组），边=parentId 层级，分层布局。
- G4 交互：平移/缩放/拖动节点；点击节点→在侧栏打开对应实体卡（角色面板/设定面板）并高亮。
- G5 实时性：订阅 M2 的 book:changed 事件，数据变了图自动刷新。
- G6 空状态：无角色/无设定时的友好引导。
- G7 双主题：图配色跟随深/浅主题（用 M1 的 CSS 变量 token）。

## 3. 非目标（明确推迟）

- ❌ 剧情线/关键选项/伏笔三种图：这些实体的数据主要由 M4 的 AI 整理产生，M3 时新书记不住多少，做了是空壳——随 M4 数据成熟后点亮（沿用 M1"schema 全做、UI 分步点亮"的裁定）。
- ❌ **点击节点跳转到章节**（上游规格 §8 M3 行原话"点击导航到章节"）：⚑ RULING——**推迟到 M4**。理由：章节归属需要"实体→出场章节"索引，而该索引由 M4 的 AI 整理闭环建立；M2 的数据模型里角色/设定不记录出现在哪些章。M3 强行做只能全量扫正文（违背分层上下文原则）或留空。故 M3 的点击行为降级为"打开实体卡"，章节跳转待 M4 索引就绪后补。这是诚实的依赖排序，代价：M3 演示时点击不能直达章节（可接受，实体卡里能看到详情）。
- ❌ 图内编辑（拖节点连线创建关系）：交互面大、易误操作；关系编辑保持在 M2 的角色面板里。图是只读视图。
- ❌ 大规模图的极致性能（几百节点虚拟渲染、WebGL）：写作场景单书角色通常 <100，React Flow 默认够用。

## 4. 关键设计选择（⚑ 均可推翻）

- ⚑ **渲染库 = @xyflow/react v12（React Flow）**。上游规格 §6 已建议它；MIT、支持 React 18、Vite/Electron 兼容、自带平移缩放拖拽。这是 M2(js-yaml) 之后第二个新增运行时依赖——项目一直克制，此依赖换来的是不自造缩放/拖拽/连线的巨大轮子，值。备选（Cytoscape.js / D3 手搓）更重或更费工，不选。
- ⚑ **布局 = 纯函数自算，不引 dagre/elk**。人物关系图用**径向布局**（角色按度数排序放圆周，中心放主角）；世界观图用**按分类分列 + parentId 纵向分层**。理由：这两类图结构规整，手写布局 ~80 行纯函数即可、且可单测；引布局库是多一个依赖 + 打包体积。若实际效果对稠密关系图打结严重，M3 内允许追加 dagre（记为计划修订）。
- ⚑ **图视图位置 = 主区切换，不新开窗口/面板**。顶部一个 `写作 | 图谱` 分段控件（Segmented），选图谱则主区渲染图、选写作则渲染编辑器（互斥，同一 renderMainView 出口）。理由：兑现 M1 预留接缝；图谱是"通览"场景，全屏主区最舒展。备选（右侧抽屉小图）太挤，不选。
- ⚑ **两种图 = 图谱视图内二级切换**（`人物关系 | 世界观`），复用同一张画布组件、只换数据选择器+布局器。
- ⚑ **数据获取 = 渲染层经现有门面拉取**：`character:getAll` + `setting:getAll`（volume 暂不入图，卷是章节组织维度不是实体关系）。纯选择器函数把 M2 数据 → `{nodes[], edges[]}`，与 React Flow 解耦、可单测。订阅 book:changed 重拉。
- ⚑ **点击节点行为 = 打开侧栏对应 tab + 选中该实体**（角色→角色面板高亮；设定→设定面板定位）。不改编辑器当前章。
- ⚑ **只读 + 无向渲染**：关系边按 EntityLink 单向画（A→B 带 kind 标签）；若 A、B 互设了关系，画两条或合并（M3 取"各画一条有向边"，简单不丢信息）。

## 5. 架构与文件划分

```
src/renderer/
  pages/Workspace/
    index.tsx                     # 顶部加 写作|图谱 Segmented；renderMainView 按 view 分支
    hooks/useGraphData.ts         # 新：拉 character/setting + book:changed 订阅 → 原始实体数组
  components/Graph/
    graphModel.ts                 # 新·纯函数：entities → {nodes,edges} + 布局（可单测，无 React）
    graphModel.test.ts            # 单测：节点/边计数、径向坐标、层级、自环/悬挂边处理
    GraphView.tsx                 # 新：React Flow 容器 + 人物/世界观二级切换 + 空状态
    CharacterNode.tsx / WorldNode.tsx  # 自定义节点（角色按 role 着色、设定按 category 着色）
    graph.css                     # 新：React Flow 主题覆盖，全部走 var(--color-*)
```

- `graphModel.ts` 是核心且纯：`buildCharacterGraph(chars): Graph`、`buildWorldGraph(entries): Graph`，输入 M2 类型、输出 React Flow 的 nodes/edges + x/y。所有边界（空、单点、自环 targetId===自身、悬挂 targetId 指向已删实体、互斥双向边）在此处理并单测。
- React Flow 只负责渲染/交互，不懂业务——业务全在 graphModel。

## 6. 约束

- 新增运行时依赖仅 @xyflow/react（+ 其自带 CSS，需在入口引一次）。
- 不改 M2 数据模型、不改 IPC 通道集合（只消费现有 getAll）。
- 图配色一律走 CSS 变量，深/浅双主题实测无闪、无不可读文字。
- 遵循全仓既有门禁：typecheck 0（入 build）、lint 0 error、vitest 全绿、每任务提交带 Co-Authored-By。
- 中文文案；App 名"完美小说"。

## 7. 验收（M3 DoD）

- 一本有若干角色+关系的书：切到图谱→人物关系图，节点数=角色数、边数=有效关系数、径向无重叠、可平移缩放拖拽。
- 世界观图：设定按分类成组、parentId 成层级。
- 点角色节点→侧栏跳到角色面板并选中该角色。
- 在角色面板新增一个关系→图（订阅刷新）出现新边，无需手动刷新。
- 空书→友好空状态；删光角色→回到空状态不崩。
- 深/浅主题切换，图配色跟随、文字可读。
- graphModel 单测覆盖上述边界；全门禁绿；人工冒烟（真机看图谱）由发起人补做。

## 8. 与后续里程碑的接缝

- M4（AI 维护闭环）：产出"实体→章节"索引后，把本视图的"点击打开实体卡"升级为"点击可跳章节"，并点亮剧情线/选项/伏笔三种图。
- 本设计已把"图从哪来"与"图怎么画"彻底解耦（graphModel 纯函数），M4 加数据不改渲染层。
